## The language

- **One text format for nine kinds.** The first line is `diagram dfd|flow|cloud|sequence|state|class|mindmap|timeline|er "<title>"`. A file may hold several diagrams: each later `diagram <kind> "<title>"` line at column 0 opens another frame, and frames are named by their titles, which are unique (ADR 0031). A node is a name with an optional `[kind, key: value, ...]`; links are `>` one way, `<>` both ways, `-` no arrow, `-->` dashed and `--` dotted with no arrowhead (a class diagram keeps `--` as its association), chains allowed, and commas fan out (`A > B, C`, at most 100 links a statement), a label after `:`; groups are `Name { ... }` with an optional `[icon: ..., color: ...]`; `//` starts a comment.
- **The attributes are `id`, `icon`, `label`, `color` and `table` (step 11).** The writer writes them after the kind word in that order, `Retry 2 [step, label: Retry, color: danger]`, and a canvas edit puts a new one in its place in that order. `id` is still the number a data flow shows (`1.0`, `D1`); it is not the shape's identity. `table` is `schema.table`.
- **The name is the identity, `label:` is what the shape shows (step 11; eraser.io `label`, Mermaid `id[label]`).** Names stay unique. A shape with `label:` shows the label in place of its name, on the canvas and in Publish, and is sized by it. Lines, groups, completion and the Assistant still name it by its name. A label may repeat, so two shapes can show "Retry".
  - **The canvas writes `label:` only when the typed name is taken.** Typing or adding a name that another shape or group already has keeps the shape: it gets the next free name, as adds do (`Retry 2`, `Retry 3`), plus `label: Retry`, and the strip says so. A file with no repeated words keeps no `label:` at all. This replaces the refusal "Retry is already used." on the kinds below.
  - **Editing a labelled shape edits the words it shows** (`src/flow/labels.ts`, one edit list and one undo step). Words that are free as a name become its name and the label goes; lines that named it follow. Words that are taken change only `label:`, and no line moves. Another shape's line is never rewritten to tidy it.
  - **Where it applies:** the kinds whose shapes are written `Name [..]` (`ATTR_DIAGRAMS`): flowchart, data flow, state, cloud and mind map topics. Participants (`participant X`), classes (`class X`), timeline items (`2026-10-19: X`), the central idea (`root X`), notes, `[*]` markers and group names keep the refusal; groups stay unique. `label:` or `color:` on a sequence or class shape is an error with a fix that removes it.
  - **The label value** is quoted by the `RESERVED` rule, plus `,` (`attrValue`).
  - **Completion lists each shape by its name**, with the words it shows in the detail column: `Retry 2  shows "Retry" (label:)`. A shape is offered when its name or its label starts with what is typed. The `label` and `color` keys say what they are for, and after `color:` the six presets come with what each means, and the CSS colour names follow with their hex.
  - **A line end that matches only a label** is an error with a fix: "Retry is a label: lines name a shape by its name, so write Retry 2." When the label is shared it says "Several shapes show Retry: a line names one by its name." and offers each name.
- **`color` is a preset, a CSS colour name or a hex (ADR 0031; was six palette names in step 11; PRODUCT.md principle 5).** The presets are `accent`, `info`, `success`, `warning`, `danger` and `muted`, drawn in their theme tokens. Beside them `color:` takes any CSS colour name in any case (`teal`) or a hex of 3, 4, 6 or 8 digits, quoted or bare; the writer writes a hex quoted (`color: "#3b82f6"`). A custom colour draws its outline in the colour, its fill as a light tint over the surface and its words in the theme's text colour, so a dark colour stays readable on the dark theme. `colours.ts` holds the name table.
  - A value that is none of these is a hint (the drawing stays; the shape draws in its kind's colours) with a quick fix. A near miss offers the closest name ("tael is not a colour. Did you mean teal?"); anything else says "Use a preset such as accent, a CSS colour name such as teal, or a hex such as \"#3b82f6\"."
  - Nodes, groups (`Dispatch [color: muted] {`) and lines take it, in the kinds above. Groups take `icon` and `color` only.
  - **Lines take attributes after the label: `Paid? > Retry: no [color: warning]`** (eraser.io connection syntax; user ruling, 1.0), or straight after the last name with no label, `A > B [color: success]`. A trailing `[..]` reads as attributes only when every key in it is a known attribute; otherwise it stays label text, so labels that end in brackets (`see [note 1]`) read as before. A line takes only `color` ("A line takes only a colour, for example [color: warning]."); sequence, class and timeline lines take none. In a chain the colour is the last link's, as the label is, and a coloured link is written on its own line. The canvas writes it with `setLinkColor` (the link's ref; a link inside a chain is split off first).
- **Participants take attributes (ADR 0031).** `participant` and `actor` lines take `[icon: .., color: .., label: ..]`. Written participants come first, in the order written, then the rest by first use.
- **The ER kind returns in table blocks (ADR 0031).** `orders [icon: x] { id int pk }` with one column per line; relationships `>` many to one, `<` one to many, `-` one to one and `<>` many to many, between `table.column` ends or whole tables, resolved by the longest prefix that names a table. Groups are `group Name [..] {`; `[weak]` marks a weak table. The old form (`table.column type`, `1--*`) is detected, carries the fix "Rewrite as table blocks" and refuses edits until rewritten. Open as DBML reads either form.
- **Cloud adds `..>`.** A dotted "assumes" line, a permission rather than data. The text reads it one way, from the first name to the second; the canvas draws it dotted with no arrowhead, as frame 6+.5 does. Only cloud diagrams accept it. Mermaid import never writes it; the canvas writes it only when the user picks "Dotted (assumes)" in a cloud line's Arrow menu (ER build B).
- **ER columns took flags (ER build A, 2026-10-24; removed by ADR 0030).** A column line is `table.column type`, optionally followed by `[pk, not null, unique]` (any of the three, any case; the writer writes them in that order and each as it is, so toggling one never changes another; a key is read as not null whether or not the list says so). The canvas writes column names of letters, digits and `_` only, and types without the characters the line reads as syntax. Each canvas column gesture (add, rename, retype, a flag, duplicate, delete) is one line edit and one undo entry.
- **A state composite's own start and end (diagram build 4, fix round 1, 2026-10-25).** In a state diagram, `[*]` in a line written inside a composite's braces (`Active { ... [*] > NumLockOff ... }`) is that composite's own start or end, as in Mermaid's composite states. The parse names it `[*] start in <Composite>` or `[*] end in <Composite>`, makes it a member of that composite and draws it inside it. `[*]` outside every composite is still the diagram's one start and end (`[*] start`, `[*] end`), so old files read as before. The writer and the canvas put a line to a composite's own marker back inside its braces; a line end is never moved onto one. `model.ts` names and reads them (`stateMarkerName`, `isStateStart`, `isStateEnd`, `isStateMarker`). Mermaid's `--` (parallel regions) has no `.flow` form: the importer refuses that line with its reason. Mermaid pasted inside a composite's braces goes in where the paste is, so its `[*]` lines read as that composite's own (diag-910 fix round 2, N11). Ungroup turns a composite's own `[*]` lines into the diagram's and says so; a copy leaves out the lines to a composite's own `[*]`.
- **Quoting.** One rule for the parser and the writer: `flowModel.ts`'s `RESERVED` (brackets, braces, `:`, `>`, `<`, quotes, a backslash, `//`, a lone `-`, `--`, a line break) puts a name in double quotes with backslash escapes (P2). Line breaks in names and titles are escaped as `\n` and `\r` and read back by the parser and by the Core's scanner (P5).
- **The parser runs in the language worker** (`src/lang/flow/parse.ts`, `service.ts`). It returns the `FlowDoc`, the problems with their fixes and the last good drawing. Ranges stay in the worker: the tab asks for spans, edits and completions by text version, and a request for an old version is answered "stale" (P5, P8).
- **Edits from the canvas are text edits.** `src/lang/flow/edits.ts` returns minimal changes for add, connect, rename, delete, group join and leave, attributes and line colours; the tab applies each list as one CodeMirror transaction, so text and canvas share one undo history. Moves write only the layout file; the `.flow` is not touched (P24).

## Files

- A diagram is `<name>.flow` plus `<name>.flow.layout.json` in `<data>\diagrams\` (answer 1B). The Core builds every path from the name: `list_diagrams`, `read_diagram`, `write_diagram`, `write_diagram_layout`, `rename_diagram`, `delete_diagram` (the Recycle Bin) and `save_diagram_copy` sit on step 7's `write_flow_files` and `PathUse::Flow`, with no second guard (P1). Step 7's own `write_flow_files` and `flow_exists` commands had no caller left and are gone; the Core functions stay (P24).
- One name rule, with the spec's text for every bad name: "Use a name without \ / : * ? " < > | and under 120 characters." It refuses separators, `..`, reserved Windows names (COM0 and LPT0 too), a trailing `.flow`, and names over 120 characters or 200 UTF-8 bytes (P1, P4).
- The `.flow` is written only after a text edit. Moves, Classic and the direction write only the layout file through `write_diagram_layout`, which goes through the same guard and refuses when the `.flow` is gone, so an edit made outside Contura while the tab is open survives them and a diagram deleted outside is never recreated (P24). A file whose every line break is CRLF is saved with CRLF after an edit; a file with mixed line breaks is saved with LF (P16).
- `read_diagram` runs off the main thread and refuses a file over 5 MB with a plain message (P24). The write and rename commands stay sync, so they run in the order sent; Replace, Rename and Delete also wait for a write already on its way (P21, P24).
- A tab's pending write is held by `flowRegistry` across close, rename, replace and delete, so a discarded tab never writes again and a failed save asks before anything is lost (P16, P17, P19, P21). A tab that closed during a held rename or delete writes its edits on the release; if that write fails, the diagram stays in the list as a failed save, so the window close guard tries again and asks (P24). Closing a diagram while its file is being moved or deleted says "Contura is still moving or deleting this file. Try again in a moment." (P24).
- Publish and "Save a copy as..." are the only ways a diagram leaves the folder.

## Lineage

- **From the catalog, never rows.** The Core's `lineage` command reads key edges with one catalog query per schema or database (MySQL `REFERENTIAL_CONSTRAINTS` and `KEY_COLUMN_USAGE`, PostgreSQL `pg_constraint` without partition copies, SQLite `pragma_foreign_key_list` once per table), then one light column read for the tables it reached. It stops at 300 tables or after 10s and says so (P6). It does not call `table_design`, which was too slow for All; a test keeps the two readers' key edges equal.
- **One table's failure is not the lineage's.** Only an error on the centre table fails the call; any other table keeps its card with the reason (P6).
- **Flows from `.flow` files.** `list_flow_table_links` scans `table:` lines without a full parse and returns the access and, for each table node, the process or step that reads or writes it. A step with a `table:` names itself; a store names the processes on its lines (P18).
- **Views.** From the catalog where the server keeps one (PostgreSQL `pg_depend`, MySQL 8.0.13+ `VIEW_TABLE_USAGE`), worded "reads"; otherwise a name match, worded "names", with a note when the catalog read failed (P14, P18).
- **"Before you delete".** The warning reads its own `usedBy` lineage, independent of the toolbar, checks every key column's nullability and defaults, and says "This list may be incomplete." with the reason when it is (P14, P15). While that read runs the block shows its title and "Checking what deleting an order does...", never nothing; Try again keeps the last result on screen while it reads again (P24).
- **No Tidy button.** Lineage's layout is computed, so Reset layout is its Tidy: every moved card glides back with the Tidy timing and the layout file is removed (P23).
- **Layout.** `<data>\diagrams\.lineage\<hash>.layout.json`, named by the first 32 hex digits of a SHA-256 of the Connection, database, schema and table, so no table name reaches the file system; at most 1 MB, through the diagrams guard (P18).

## The icon pack

- `scripts/pack-icons.mjs` reads the official packs from a local folder and writes `src-tauri/icons-pack/icons.bin`: 4,625 names, about 3.1 MB, inflated one icon at a time by the Core (`icon_index`, `icon_sets`, `icon`). The front end keeps at most 200 icons and loads only the ones a diagram shows. The licences and how each set was read are in `docs/research/2026-10-18-icon-licences.md`.
  Amended 2026-10-26 (Plan C): every icon is fitted into one 24 by 24 frame by rewriting only its root start tag, so the drawing stays byte for byte (a hash of everything after the root tag proves it) and nothing is cropped, stretched, flipped or redrawn; each set has its own margin and Lucide's stroke is 1.5. Outline icons (Lucide) and logos (Simple Icons) keep one copy in the pack and the Core adds the theme's text colour as `color` when it serves them (`#1f1f1f` light, `#f8f8f2` dark, the `--c-text` values), so they follow the theme; colour icons from the clouds and Kubernetes are never inked. Owner rulings 26 Oct: a logo is inked in its brand colour (the pack's `hex`, from Simple Icons' data), since WCAG exempts logos from its contrast rule, down to 1.5:1 on the theme's canvas; below that a pale logo on light keeps its colour with a hairline in the text colour (a CSS drop-shadow on the canvas, one filter of primitives in the published SVG) and a dark logo on dark is drawn in the text colour. The front end picks the ink and the outline and the Core still only validates the ink. The served text, ink included, passes the safety check again, and `color` is now an allowed presentation attribute. Names keep today's scheme and a stability gate in the pack script fails the build if a name of the previous pack stops resolving (`RENAMED` or `DROPPED` are the only ways out). The 4 MB cap is checked by the script, by `pack_under_4mb` and by a 3,700,000 byte target for the brand list; the cap is never raised. Icon credits names each set's change (`changes`), and the Simple Icons logos with a CC-BY-SA licence of their own are marked as adapted files shared under the same licence.
- **Icons are untrusted data.** They are downloaded outside the repo and only the pack is committed (P7). Each SVG passes an allow list, identical in Rust (`icons::unsafe_reason`) and in the script, tested against one shared fixture list: UTF-8 with no control bytes, allowed element and attribute names only, `href` only to a `#fragment`, CSS limited to a plain character set and `url(#...)`, no comment that could close early, under 256 KB (P9, P10, P13). The check runs again when an icon is served.
- **Icons are only ever images.** The UI shows an icon as an `<img>` of a `data:` URL, never as markup, and Publish embeds each one as an SVG `<image>` of the Core's served bytes (P7, P9). The drawing is never redrawn, recoloured, cropped or flipped; only the frame and the ink change (see the amendment above).
- **Icon credits** shows each set's licence and source as plain text. An https source is a link that the Core's `open_url` opens in the system browser: the Core checks it again (https only, no user name or password, no spaces or control characters, at most 2,048 characters) and hands it to the shell with `ShellExecuteExW` (no Windows error box; Contura shows the error). The webview never opens a window of its own.

## Canvas and motion

- **Guides, not a grid (ER build B, 2026-10-24; erd-ux-research decision 1, diagram-ux-research F7, F26, F32).** No canvas snaps to the 16 px grid any more: a drag follows the pointer, and an edge or the centre of the dragged cards snaps to an edge or centre of a shape on screen within 6 screen px, drawn as a 1 px accent guide (`src/diagram/guides.ts`, an index sorted per axis built once a drag starts, so a frame stays cheap at 2,000 shapes). Alt moves freely, Shift keeps one axis, Esc puts the cards back. Drops, new shapes, pastes and Tidy keep whole pixels. Arrows move 1 px and Shift+arrows 16 px; a held key's repeats are one undo entry. A resize takes Shift (keep proportions), Alt (around the centre) and Esc; a double-click on an edge, or Fit to content, drops the kept size. The dot grid stays as a backdrop. Every canvas, the Schema Builder, query diagram and lineage included, selects by dragging empty canvas.
- **Lines change on the canvas (diagram step 4).** The canvas names a line by its two ends, its label and which of the lines with those it is, never by an index into a drawing that may be stale; a line it cannot find, or a text with errors, is refused with the reason (fix round 1). The writer sets a line's arrow to one its kind draws (`setLinkArrow`), reverses it (`reverseLink`) and moves one end (`setLinkEnd`, dragged from a selected line's end handle). A link inside a chain splits the chain into one statement per link; everything else stays byte for byte.
- **ER relationships joined columns (ER build C, 2026-10-24; removed by ADR 0030).** A line's end may name a column, `invoices.customer_id *--1 customers.id`: when `table.column` is no node of its own and `table` is an entity, the end is that table and the column goes beside it (`FlowLink.fromColumn`, `toColumn`), read once every column line is in, so a line may come before its columns. A column the table does not have is a problem ("customers has no column idx."); a quoted end is always a name. Table-to-table lines read and draw as before. Renaming a table rewrites only the table's part of each column end; renaming a column rewrites the lines that name it; deleting a column deletes them; each is one edit list. On the canvas (board ER interactions, fix round 1) a drag from a column's port onto a column joins the two at once (the key end is "1": key to key `1--1`, otherwise `*--1` written from the referring column); onto a table's header it joins that table's key (a table with no key refuses). A drag from a table's own port onto another table, or "Add relationship to...", adds the target table's singular name plus its key (`customers` gives `customer_id`, by the Rails inflector's singular rules, irregulars and uncountables, ported as they are; a table in capitals gets the key in capitals, a PascalCase table is written in snake case as Rails' `foreign_key` does) to the source table, of the key's type and not null, and joins it, as one batch; when the source already has that column (ignoring case) it is linked and nothing is added (fix round 2). A column's menu has "Make a relationship from here": the next column picked, by the pointer or by arrows, Tab and Enter, or a header for its table's key, gets the relationship. The keys offer only places that make a line and are taken only from the drawing's pane (or the page, when focus was lost); Esc, focus going elsewhere, a dialog, Publish or any other action ends it. A notice about a written edit goes when the text changes from it (an undo); refusals stay until the next canvas action. A loop is made column to column; a column dropped on its own table's header is refused, and so is an end `table.column` that also names a node. Integer widths, text kinds and decimal kinds each join within their family. Each frame a line at its rows routes and allocates as a line at its middles does (measured in `guides.perf.test.ts`); its scroll is two listeners made when the line is drawn, not per frame. A relationship's end dragged keeps these rules; a table with no key, or a drop on its body, leaves the end on the whole table and the strip says so. The lines meet each card at the column's row and follow the rows as they scroll; a row scrolled out of view puts the end on the card's top or bottom edge (DataGrip, dbdiagram); two columns of one table loop on its right. A table added by a double-click on the empty canvas is `table_1`, `table_2` (`sqlFreeName(name, taken, 1)`), and is not written until its name is kept.
- **ER free names (live check, 2026-10-24; removed by ADR 0030, the rule lives on in the Table Designer's column paste).** A copied, pasted or added ER table whose name is taken becomes `orders_2`, then `orders_3`, so it stays a plain SQL name; names are compared ignoring case, as SQL does, and only a `_N` the app added counts on (`log_2024` copies as `log_2024_2`). The other kinds keep `Step 2`. Resize and Fit to content are undo entries of their own.

- **Colour comes from the selection's menu (step 11; draw.io Fill, Miro, eraser.io `color`).** Right-click a shape, a selection, a line or a group title, then Colour, then one of six swatches or Clear colour. Shift+F10 and the menu key open the same menu, and Right opens the submenu.
  - Each swatch shows its name, what it means and the word the file gets (`color: danger`); the Colour row shows the colour now, "none" or "mixed".
  - One pick on several shapes (and selected lines) is one edit list and one undo entry. Clear colour removes the attribute and drops empty brackets.
  - Where a colour cannot be written (sequence, class and timeline shapes, notes, `[*]` markers, the central idea, class lines) Colour is greyed out and its tooltip says why. A mind map branch and a sequence message have no Colour row.
  - Each name reads theme tokens (ADR 0008, `PALETTE_TOKENS` in `src/diagram/types.ts`): fill `--c-<name>-subtle`, border, line and group title `--c-<name>-text`, words `--c-text`; `muted` is fill `--c-bg-active`, border `--c-text-subtle`, words `--c-text-muted`. The `-text` tokens are the borders because `-solid` fails in places (light `--c-warning-solid` is 2.2:1 on the canvas). Every pair passes in both themes: border 5.6:1 or more on the canvas and on menus, words 6.2:1 or more on the fill.
  - A coloured line keeps its colour and its arrowhead (one marker per colour), selected too, and grows to 2.5 px when selected. A selected coloured shape keeps its colour and shows a dashed selection frame. A coloured group takes it on its border, tint and title.
  - Group colours and Production orange are left out of the palette: they already mean "whose data" and "production".
- **A new shape from Shapes, a key or Add here goes to a free spot near the middle of the view, clear of the group frames as well as the shapes** (step 11 board note: a third Retry had landed on the Dispatch frame). The free spot rule is the same (`freeSpotNear`); the frames are obstacles too.
- Node kinds `process`, `store`, `external`, `start`, `end`, `step`, `decision`, `io`, `subprocess` and `service` join the engine with their own token pairs; Modern is the default look and Classic draws the Gane-Sarson shapes, kept per diagram in the layout file (answer 6A).
- Lines route square with 8 px corners (`src/diagram/route.ts`); labels sit on chips; arrowheads are 6 px.
- **One motion table.** Every timed move reads `src/diagram/motion.ts`, and reduced motion (the system setting or the app's own) makes each value 0. Nothing loops; typing, selection, panning, wheel zoom and the dragged node are never animated.

- **Boards on one canvas (Plan B1, 2026-10-26).** Decisions in order of the plan.
  - One canvas, one live frame (decision 1). The selected frame's shapes are live nodes with bare-name ids. Every other frame is a static frame node with its shapes as children, ids prefixed `\u0000in:<title>\u0000`, and none of them selectable or draggable. A frame that stays static across a switch keeps its node objects. The prefix `\u0000frame:` stays a sequence loop box's.
  - Origin and nothing selected (decision 2). `FrameLayout.at` is a frame's origin and node positions are frame-local. Selecting a frame shifts the viewport and the nodes in one store update, so nothing moves. With nothing selected no frame is live. A board of one frame opens with it selected, a larger board opens with none and fits. A switch fades the canvas over `motionMs("enter")` because a 200-node switch measured 203 ms in the release WebView.
  - Selection levels (decision 3), as Figma has them. A click on a shape selects the shape and its frame, a click on a frame's tab or its empty space selects the frame, and Esc goes up one level.
  - Frames size themselves (decision 4): the bounds of their shapes plus `FRAME_PAD` (40), at least `FRAME_MIN` (320 by 200). The title tab sits above the top-left corner.
  - Moving and z-order (decision 5). A frame is moved by its title tab, drawn static while dragged, and `at` is written as one undo entry. Overlap is allowed. The canvas runs `zIndexMode="manual"`, set by `FlowTab` only.
  - Tool keys (decision 18). A letter arms a tool. Shapes, lines and text return to Select after one use, and Pen stays armed until Esc or V. `KIND_TOOLS` is the one source of keys. N adds a note inside a frame whose kind has notes and arms the note sketch elsewhere.
  - Kind tools (decision 19) carry the Shape picker's shapes. A generic rectangle, ellipse or diamond started inside a frame writes that kind's shape where one fits, else a loose sketch.
  - F draws a Section (decision 20): a titled box of sketches that moves the sketches wholly inside it. It is no diagram.
  - The Shelf and the Space box (Plan B2, decisions 2 to 9, 11, 18 and 19). Add opens the Shelf, a panel that does not block the canvas. It has two sides: Diagrams on the left (kinds, icons and shapes, `SHELF_TABS`) and Templates on the right, with one search over both. Tab switches between the sides, and a screen reader hears which side is shown. Any press outside the Shelf closes it. A shape the open diagram cannot hold shows as disabled, with the reason. Add puts a new diagram in the middle of the view, while Duplicate puts it beside the original. A tile can also be dragged onto the canvas (`SHELF_DRAG_TYPE`). The Space box is the small add box a Space tap or `/` opens at the pointer; Enter drops the pick at its crosshair (`spaceResults`). Tab grows it into the Shelf. It closes when the view moves or the canvas resizes. It opens while the Assistant is editing too, but every add from it is refused. Add here (the context menu) keeps the free spot rule above. Board templates are saved with a version 1 layout (decision 18), so older Contura reads them. A frame is added with `addFrames`, which the worker runs as `appendFrames`. "From Mermaid" and "From my database" add a new diagram, and a typed Title names it. Home's New diagram opens the same catalog in a dialog. Two seams are left for Plan C to change (decision 6): the icon source (`makeShelfIconSource`) and the template list (`BOARD_TEMPLATES`).
  - Sketches (decision 21) are rectangles, ellipses, diamonds, lines, arrows, pen strokes, text, notes and Sections in the layout file. They are children of one layer node placed at minus the origin, so an origin shift moves one node. A diagram frame never moves sketches.
  - Space (decision 26). Holding Space and dragging pans. A tap (under `SPACE_TAP_MS`, 250 ms, with the pointer moved under 4 px) opens the Space box at the pointer, and `/` does the same. A Space tap with the pointer off the canvas opens the Shelf instead.
  - Keyboard and zoom keys (decision 28). The toolbar is a WAI-ARIA toolbar with one tab stop. Frame tabs are buttons in frame order. Shift+1 fits the board and Shift+2 zooms to the selection or the selected frame. Every glide reads `motionMs("fit")`.
  - `FlowTab` across a switch (decision 29). `frameKey` is `frame#${doc.frameId}`, so a rename keeps the selection. Per-frame state resets in `useFrameSwitch` before effects compare one doc with the next, so a switch never reads as every node deleted. An Assistant run is held to one frame: Tab, click, Esc and pane-reveal switches are refused with the `lockedSwitch` note, and a typed switch wins and makes the plan stale. Keys typed inside an aria-modal dialog are ignored by the board. Under reduced motion the switch fade and every glide (`glideOptions`) take 0 ms.
  - The code pane (decisions 14 to 17). The pane stays on the left. It is one `.flow` document with the other frames hidden by block replace decorations, so one history covers the whole file. User edits that touch a hidden range are dropped. An undo or redo whose change lies in a hidden range shows that frame, through the `historyReveal` transaction extender in `frameView`, because history dispatches with `filter: false`. Line numbers count from the shown frame's header, in the gutter, Problems, the stale banner and the status bar. Each tab remembers whether its pane was open, in memory by file name for the session, and a tab opened for the first time opens with the pane open. A hidden pane takes no space. With nothing selected the pane shows frame 0. Problems list the shown frame's problems, another frame with problems shows a count on its tab, and `tooManyFrames` shows as a banner.

- **ER editing on the board (Plan B3, 2026-10-26, amended 2026-10-27).** An ER table's card edits in place in the live frame; the rules that keep a board of ERD frames cheap are these.
  - Live is per node. React Flow draws every node through one renderer, so no provider can wrap only the live frame. The card contexts sit around the whole canvas and every reader gates on the node: `useErLive()` is `!isStaticId(id)`, and `useErCard`, the scroll and sole-table readers, the ports and the card's handlers subscribe to nothing in a static frame. `isStaticId` lives in the leaf `src/flow/board/staticIds.ts`, so the card code never imports the scene.
  - One store per tab, `createErStore()`, holds the open edit, the selected column and the aim. Its subscribers are keyed by table, so a write wakes only the tables it touches, and `useErCard(table)` returns the same slice object while it is unchanged. Scroll entries are dropped for tables a parse no longer holds. A card at rest holds nothing.
  - A card draws at most 20 rows (`ER_MAX_ROWS`) and only the rows in view plus `ER_ROW_OVERSCAN` (1) above and below, so at most 22 row elements with spacers for the rest. The window comes from the visible pixel range (`erRowWindow`, `erViewH`), not from a whole-row count, so no blank strip shows at the bottom of a scrolling card. Static frames do not scroll. Ports show only on the hovered card (kept `PORTS_LINGER_MS`, 150 ms, after the pointer leaves) and on the table selected alone.

## Publish

- Every diagram kind and lineage export through the step 6 scene and Publish dialog. The scene gained drawn nodes (with their look, second line, id, link mark and icon), group areas and `flow` lines (dashed or dotted, heads at the end, both ends, the start or none, a label chip). `src/flow/flowScene.ts` and `lineageScene` in `src/lineage/scene.ts` build them from what the canvas draws.
- **Every kind as the canvas draws it (publish-parity, 2026-10-25).** The scene also carries a sequence's frames, a timeline's sections and axis with its ticks, a participant's activation bars and a topic's level; lines may be `message` (straight along its row, a reply dashed with an open head, a message to itself looping out right) or `branch` (a mind map's curve), and a class line's ends are marks (hollow triangle, filled diamond, filled or open head). `sceneToSvg` draws participants with their heads and dashed lifelines, class cards with the name band and member rows, the mind map's root and topic pills and plain subtopics, timeline events, period pills and milestones, notes as square-cornered notes in every kind that has them, and the flowchart document and database. Frame and section tints read `--c-bg-panel` (the palette's `panel`). A folded topic publishes folded. The New diagram card for a sequence uses this same path; its own small drawing is gone.
- **Colour and labels (step 11).** A labelled shape publishes the words it shows. A coloured shape, group or line publishes in its palette colour, arrowheads included. The export palette reads the six colours from the theme the Publish dialog picks, light or dark (`exportPalette(theme).colours`), so an image follows the chosen theme as every other export colour does.
- The crop box snaps to node and group edges within 8 screen px, as the direction spec asks; Alt turns it off, and a kept aspect is not bent by a snap.
- The PNG path frees its canvas and image as soon as the file is encoded, and closing the dialog drops the scene.
- **Publish on boards (B4).** A board publishes through the same dialog, with a source for the board (`boardSvg.ts`, `source.ts`). The part control reads Whole board, Selected frame (the frame and the sketches wholly inside its box), Selection and What's on screen, and opens on the selection: shapes or sketches selected give Selection, a selected frame gives Selected frame, nothing gives Whole board. Frames draw as the canvas does, in text order: each frame's box and title pill (kind icon, kind word, title), under the sketches that draw above frames, with Sections, rectangles, ellipses and diamonds below the frames and every other sketch above. A "Frame titles" switch, on by default, leaves out the boxes and pills. Frames keep their places and gaps; Padding is the only margin. A frame with nothing drawn, and a frame whose title another frame took first, are left out and counted in the note. The image holds one `<defs>`, with the hairline filter and each icon once as a data: image drawn through `<use>`, and every id is unique and the same across two exports of the same content, so two SVGs can sit in one page. Sketches draw as the canvas draws them, in both themes, and the composer holds one frame's scene at a time; the dialog keeps at most two drawings, and a crop or padding change rewrites only the head. Past the limits (a PNG side over 16,384 px, a PNG over 40,000,000 pixels, an SVG over 24 MiB; the same limits apply to single diagrams and to the Schema Builder's Export as PNG) the PNG scale steps down, then PNG turns off, then Copy and Save as turn off, each with one line in the note; the limits are provisional until the release-build measurement and are never raised. Ctrl+Shift+E, the strip's Publish button and the empty canvas's "Canvas actions" menu ("Publish image...") open Publish when any frame has something drawn (a board of sketches only cannot publish), and the frame bar's `⋯` has "Publish frame..." (off for an empty frame) and "Publish board...". A board of one frame and no sketches still publishes as before, byte for byte, through the diagram source, and draws no box or title pill, a stated difference from the canvas. A frame with an error draws its last good drawing at full strength; the canvas fades it. An ER table of more than 20 columns publishes every row (the canvas scrolls them): its frame's box grows down to hold the card, and so do the Whole board and Selected frame regions, so no row is cut off. The grown box may overlap a frame placed below it, a stated difference from the canvas. A Section's title, above its box, counts in the region. Each `<use>` carries `xlink:href` beside `href`, with the xlink namespace declared once on the root, so SVG 1.1 readers (Inkscape before 1.0, older librsvg) draw the icons.

## Memory and large diagrams

- Parsing and layout run in the language worker; over 300 nodes the canvas runs in fast mode and draws only what is visible.
- A canvas change, and the end of a glide, keep the measured size of every node that draws the same (same type, size and data), because React Flow draws every node it has not measured: before this, each edit, move or Tidy drew all 2,000 nodes of a large diagram for a frame. A node whose content changed is measured again, so its ports stay right. This holds for canvases whose node data is stable between changes (the drawn diagrams and lineage); the Schema Builder builds new card data on every change, so its cards are measured again (carried, not a regression).
- `large_flow_2000_nodes_smooth` checks fast mode, visible-only drawing and the frame time of a drag frame in jsdom; the parse, edit and glide budgets are the worker gates in `npm run test:perf` (best of three 20-run medians under 16 ms, P8).

- **Boards at the limit (Plan B1, 2026-10-26).** The limit is 50 frames and 10,000 shapes, with 1,000 sketches and a 5 MB layout file.
  - Only changed docs cross the worker (decision 13). Each `FlowDoc` has an identity number, and the worker leaves out a `doc` or `lastValid` the client already holds. `toWire` and `fromWire` (`src/lang/flow/wire.ts`) fill them back before a request resolves, and a miss sends `flowResend`. Plan A Task 5 measured 13.4 of 19 ms per keystroke on a full board as the cost of cloning 50 frame docs. Task 1's gate is under 12 ms, and unchanged frames keep their object identity for the canvas memo.
  - The scene keeps one memo entry per current frame key, and keys that are gone are dropped on every build (decision 27). `detailFor` counts only the live frame's shapes, so a 10,000-shape board is not forced into fast mode. This is intended until Plan F. The MiniMap is hidden on boards with more than one frame.
  - Z bands are 30 wide (spike (a): 10-wide bands put a live frame's group areas under its own box). A static frame k has its box at `30 * k` and its content at `30 * k + 26 + clamp(own, -25, +3)`. The live frame has its box at 1,995 and its content at `Z_LIVE` (2,000) `+ 25 + clamp(own, -25, +3)`. The layer of sketches sits at -2, Sections and box sketches at -1 (under every frame, as in FigJam and Miro), and pen, text, notes, lines and arrows at 3,000.
  - Sketch caps: `MAX_SKETCHES` 1,000, `MAX_PEN_POINTS` 1,000 a stroke, `MAX_SKETCH_POINTS` 50,000 a board, `MAX_SKETCH_TEXT` 2,000 characters a sketch and `MAX_BOARD_SKETCH_TEXT` 100,000 a board. The Core refuses to open a diagram whose layout file passes `READ_MAX` (5 MB), so before each save `useFlowDoc` measures the layout in UTF-8 bytes. Over `LAYOUT_SAVE_MAX` (4.5 MB) the text still saves with the last saved layout, and the note reads "Layout not saved: the layout file would pass 5 MB. Remove some sketches." Typed code is never lost.
  - Measured in Task 15 on the full board (50 frames, 10,000 shapes, 1,000 sketches): the saved layout was 1,590,575 bytes of 4,718,592; 30 keystrokes in one frame left every other frame's shapes, boxes, sketches and the layer as the same objects; the client held one document of 50 frames; reopening the board five times held under 2 MB over the first close; a frame move cost 1.6 KB of history (it was 76.1 KB until `frameBounds` cached weakly); a band shift of 49 static frames took 2.1 to 3.3 ms.
  - The canvas paints in one composited layer (`will-change: opacity` on `.diagram-canvas .react-flow`). Without it WebKitGTK gave every edge's svg its own layer, sized from the flow origin to the edge, and a board of 10 dense frames grew the web process past 3 GB with a blank canvas. A single diagram whose nodes sat far from the origin had the same hazard before boards.
  - The overview (Task 18b): below `BOX_BELOW` (0.45) every static frame draws as one cached preview (its shapes as blocks, its links as straight segments) and the live frame draws in fast mode; at 0.45 and above frames draw in full and only what is visible. The code pane takes the new frame's text after the canvas has painted.
  - Measured in the release build on Linux (WebKitGTK, this VM) on the full board: open to first paint 1.0 s (gate 3 s); a keystroke echoes in the pane in 9 to 45 ms (gate 50 ms; the canvas follows after the worker's 120 ms debounce, about 250 ms, recorded and not gated); `measure-memory.sh` 709 MB private and 1,052 MB total with every frame in view. Selecting a 200-shape frame paints in 300 to 450 ms against a 150 ms gate (290 to 315 ms without sketches); Task 0 measured this WebView's floor at about 200 ms for a bare 200-node switch. The owner accepted this for B1 (2026-10-27): the owner's Windows check re-measures it, and Plan F owns the gate, including a switch that does not move the sketch layer. Like ADR 0003's 300-table model, a full board with every frame in view is an accepted exception to the idle budget.
- **Accepted limits of boards (Plan B1).** An older Contura that reads a version 2 layout file falls back to defaults and overwrites it with version 1 on its next save, losing other frames' positions and the sketches (decision 6; accepted before 1.0). A version 2 file written while a one-frame file has an error and a stray entry heals on the next clean save.

- **ER editing at the limit (Plan B3, decision 7).** Cards draw at most 22 row elements whatever a table's size, so a 2,000-table frame draws no more rows per card than a small one. Measured by the perf gates in jsdom and node on a 2,000-table frame of 20-column tables, medians, all provisional until Task 13 measures the release build: a column edit round trip 54 to 58 ms (gate 150), a scene build 0.2 ms (gate 10), opening and closing a draft row 3.1 to 3.7 ms (gate 10), reading the column types 1.9 to 2.0 ms (gate 5), and a heap change over repeated open and close that is negative (gate 1 MB). The heap gate is weak above about 5 KB a cycle, so structural checks on the store and listener counts guard it. Thresholds are never raised to pass.

## Accepted limits

- Links to a group are valid text (Mermaid writes them) but the canvas and Publish draw lines between nodes only.
- MySQL `lower_case_table_names=2` is not handled by lineage; Aurora MySQL 3 views fall back to name matches.
- NFC and NFD forms of a name are different diagrams.
- A label is a second undo entry after the line it labels.
- The service tile's id sits beside the tile in an export; the canvas has no textbook look for flowcharts or cloud, so Classic changes only data flow.
- Publish has no pixel cap at 3x (as ADR 0017); the lineage export has no Selected nodes preset, since lineage has no selection.
- Lineage's Diagrams rows come from arrows only: a `table:` node that no arrow touches (joined only by `-` lines, or not joined) is left out, and Nothing linked says "no diagram arrow reads or writes it" rather than claiming no diagram names the table (P24).
- An edit made outside Contura to an open diagram survives moves, Classic and the direction, but a text edit in Contura afterwards saves Contura's text over it.
- Lineage tabs are outside the close guard: a card moved in the last 400 ms before closing may not be saved.
- After a zoom across a level of detail and then an edit, an off-screen node keeps the port positions measured at the old detail until it is drawn, so a line to it may end at an old port until it scrolls into view.
- Provider terms allow icons in architecture diagrams but do not name bundling in an app (Azure is the narrowest); six packed brand logos are CC-BY-SA; brand logos are trademarks. These go to the user before any release.
