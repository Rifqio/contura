~Query · SQL editor, data grid, Visual Query

Three ways in. One Run.

Type SQL with completion and VS Code keys, change rows right in the grid, or drag tables onto a canvas. Each way ends the same: you read the SQL, then you decide.

Three live windows below, each working on the same sample copy of billing in this page. A change saved in one shows up in the others.

  1. 01SQL editorCtrl+Enter runs the statement you are in, and a write with no WHERE asks first.
  2. 02Data gridEdits wait as Pending Edits. Preview the SQL, then save once.
  3. 03Visual QueryDrag tables onto a canvas and the joins come from your Foreign Keys.
+2

~01 · SQL editor

Run the statement you are in.

Ctrl+Enter runs the current statement, the one where you are typing, and leaves the rest of the file alone. Ctrl+Shift+Enter runs them all.

An UPDATE or DELETE with no WHERE would change every row, so it stops and asks: Add WHERE, Cancel, or run it anyway. Try it on the last line below.

Writing
Completion, inspections and VS Code keys.
Keeping
Query History keeps the last 1,000 statements per Connection. Saved Queries keep the ones you name.
+3

~02 · Data grid and Pending Edits

Change rows, read the SQL, save once.

Edited cells, new rows and deleted rows wait as Pending Edits, marked in the grid and counted in the bar below it. Nothing is written yet.

Preview SQL shows the statements Save will run, and Save runs them all in one transaction. On a Production Connection, Save becomes Save on PROD and asks before it writes.

+4

~03 · Visual Query

Drag, drop, joined.

Pull tables from the tree onto the canvas and Contura draws the joins from your Foreign Keys. Where no key fits, drag one column onto another.

Tick columns, add filters and sorting, and the SQL below updates as you go. What it builds is a SELECT, so Run reads and never writes.
