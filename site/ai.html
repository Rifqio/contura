~AI · access per Connection, a record of every answer, your own provider

AI you control, down to the byte.

Each Connection decides what the assistant may see. Before a question leaves the PC you can read the exact text and its size in bytes, and after the answer you can read the record it left. The assistant writes SQL. You run it.

The demos on this page answer from pre-written replies and count real bytes. Nothing on this page is sent to any provider.

~01 · What the AI sees

Each Connection decides what leaves the PC.

AI access is set on each Connection, from Never send anything up to Plus sample rows. The Sends line in the Ask panel lists what the next question would carry, with its size, before you press Send.

Values in your SQL are masked on this PC and secrets are redacted before anything is sent. Sample rows are a level in Settings already, but this release does not send them; they come in a later release.

~02 · Ask, then read the record

Every answer leaves a record you can read.

Ask in the panel beside the Visual Query. The steps show as they happen: what the Connection allows, which tables were picked, how many bytes were sent and that no tools were offered.

The answer log below fills in as the answer arrives. Read it as a plain Log, as Steps with the rule and evidence for each one, or as a Diagram of where the bytes went.

~03 · Your provider, your key

Your provider. Your key, kept in the keyring.

Contura talks to the provider you set up and to nothing else. The key is saved in the system keyring (Windows Credential Manager, or the Secret Service on Linux), never in the data folder, and it is tied to the host it was saved for, so a changed base URL does not get it until you say so.

A local model works too: point a Custom endpoint at Ollama or LM Studio on this PC over plain http. Plain http to any other host is refused.

  • Its own clientAnthropicClaude models through Anthropic's own API.
  • One client for manyOpenAI-compatibleOne client for OpenAI, Groq, OpenRouter and DeepSeek.
  • The same clientCustom endpointAny server that speaks the OpenAI API, including Ollama or LM Studio on this PC.

~04 · The rules it runs under

The model only returns text. You decide what runs.

Four rules hold for every question, from the moment you press Send to the moment SQL lands in the editor. None of them can be turned off from a prompt.

  1. Input

    Only what the level allows.

    • AI access is set per Connection, from Never send anything to Plus sample rows.
    • Production starts at Never send anything and its AI Context is cleared.
    • Sample rows are not sent in this release.
  2. Context

    Cleaned on this PC first.

    • Values in your SQL are masked before sending.
    • Secrets are redacted: passwords, connection strings with a password, API keys and tokens.
    • Database text is fenced and framed as data, so instructions found in it are not followed.
  3. Execution

    No tools on database questions.

    • A database question is sent with no tools, so the model has no path to your database.
    • Only your provider is called, at the host its key was saved for.
  4. Output

    SQL you read, then run.

    • The assistant writes SQL and never runs it.
    • Each statement is checked and labelled a read or a write.
    • On Production, Run asks first, as it does for any write.
    • Every answer has a Sent record and an answer log.
