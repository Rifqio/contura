~Data · Transfer, Import, Export, Backup, Restore, Lineage, Explain

Six jobs. None blind.

Every job that moves data shows you its plan first: the type of each column, the first lines of the file, the checks a restore runs. Then you decide.

~01 · Data Transfer

Every type reviewed, then one transaction.

Data Transfer copies structure, rows or both between Connections, also across Dialects. Each column's source type sits beside the type it will become, and a column with no safe match waits for your choice.

Into PostgreSQL the whole copy runs as one transaction. If a single row does not fit its new type, the run stops at that row and rolls back, so nothing is written.

Across Dialects
MySQL, PostgreSQL and SQLite, in any direction the types allow.
On failure
The row number and the value that did not fit, and zero rows written.
+3

~02 · Import and Export

Matched before it goes in. Shown before it goes out.

Import reads CSV, JSON, Excel and SQL. File columns match by name, and every row is checked against its new column before a single one is written.

Export writes CSV, JSON, Excel and SQL INSERT. The preview shows the opening lines exactly as they will land in the file, with an estimate of its size.

+4

~03 · Backup and Restore

A backup you can read. A restore that checks first.

Backup writes Contura's own SQL script, plain text from one snapshot, with no pg_dump or mysqldump needed. Its header says what made it and what it leaves out.

Restore reads that header and checks it against the target before anything runs. On Production it asks once more, naming the file by its fingerprint, so a file changed after the check asks again.

Backup
Only reads, so it needs no confirmation, even on Production.
Restore
Shows the exact SQL from the file, then writes in one transaction.
+5

~04 · Lineage and Explain

Know what a delete takes. Read the plan first.

Lineage reads every Foreign Key into and out of a table as one plain sentence: which rows stop a delete, and which rows go with it.

Explain asks the server for its plan and never adds ANALYZE, so the query itself does not run. Full scans of big tables and the step that carries most of the cost get a mark.
