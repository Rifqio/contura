~Safety · Production, Read-only, the system keyring

Production asks. Read‑only refuses.

Mark a Connection as Production and every statement that writes waits for your yes, with the exact SQL in front of you. Mark it Read-only and writes do not happen at all.

Every window on this page works on a sample copy of billing that lives in this page. Nothing here reaches a real database.

~01 · Production asks

On Production, every write waits for your yes.

In the data grid, Save becomes Save on PROD and opens a confirm with the statements it will run. In the SQL editor, Run on a Production Connection opens one dialog that lists each statement and labels it a read or a write.

Focus starts on the SQL, so Enter does nothing until the Run button has focus. A write with no WHERE adds its warning to the same dialog and turns Run red.

Data grid
Pending Edits save in one transaction, after you have read them.
SQL editor
Reads run at once. Anything that writes asks first.
+3

~02 · Read-only refuses

Read-only means no writes at all.

Mark a Connection Read-only and Contura does not send writes. A statement that writes gets a grey band and a lock in the gutter, and Run is off with the reason beside it. Reads run as usual.

The server session opens read-only too, as a backstop. Read-only wins over Production: with both on, a write is blocked, so Production never needs to ask.

PROD Production

Contura shows the exact SQL and asks before any statement that writes, whether it came from the grid, the editor, an import, a restore, Schema Compare or the assistant.

Read-only Read-only

The app blocks every write, and the server session itself opens read-only as a backstop. With both switches on, Read-only wins.

+4

~03 · Wherever the write comes from

Every path to Production stops at one question.

The Production confirm is not only for the editor. An import into a Production table, a restore, Schema Compare's Apply, a Pending Edits save and SQL the assistant wrote all stop at the same question, with the exact SQL or the file named.

The assistant writes SQL and never runs it. When you press Run, its statements are marked Written by the assistant and go through the same confirm.

+5

~04 · Secrets stay in the keyring

Your setup travels. Your secrets stay.

Contura is one exe, or one AppImage on Linux, and a data folder beside it. Settings, Groups, Connections, Query History and Saved Queries are plain files there, so copying the folder to another PC or a USB drive brings your setup along.

Passwords and AI keys never go into that folder. They live in the system keyring on this PC, Windows Credential Manager or the Secret Service (GNOME Keyring or KWallet) on Linux, so a copied folder carries no secrets.
